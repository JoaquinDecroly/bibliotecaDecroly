Proyecto Spring Boot es.decroly.biblioteca

Biblioteca Decroly

API REST para gestionar libros y categorías

Una aplicación Spring Boot que expone el catálogo de una biblioteca como recursos HTTP: consultar, crear, modificar y eliminar libros y categorías, y filtrar libros por autor, categoría o disponibilidad.

El proyecto en una mirada

Biblioteca Decroly organiza el catálogo de una biblioteca en dos recursos: libros y categorías. Cualquier cliente HTTP puede leerlos y gestionarlos en formato JSON.

Qué permite hacer

  • Consultar el catálogo completo o un elemento por su id.
  • Filtrar libros disponibles, libros de un autor y libros de una categoría.
  • Crear, modificar y eliminar libros y categorías.
  • Validar los datos de entrada en los servicios y responder con errores 400 y 404 estructurados.
  • Documentarse sola con OpenAPI y Swagger UI, y probarse con la colección de Postman incluida.

Sin base de datos

El pom no incluye JPA ni ningún driver de base de datos. Los datos viven en listas en memoria dentro de los servicios.

Spring enlaza las propiedades biblioteca.* en el record BibliotecaProperties gracias a @ConfigurationPropertiesScan en la clase principal, y lo inyecta en el constructor de los servicios. De momento solo se recibe: los valores de préstamos quedan preparados, pero la gestión de préstamos no está implementada.

      Ficha 09

      Errores y documentación

      Los servicios lanzan excepciones propias; un único manejador global las convierte en respuestas ProblemDetail.

      404Not Found

      NotFoundException

      Lanzada al buscar, modificar o eliminar un id que no existe. GlobalErrorHandler.notFound responde 404 con el título «Recurso no encontrado».

      • No se encontró el libro con id: {id}
      • No se encontró la categoría con id: {id}

      La clase lleva @ResponseStatus(HttpStatus.NO_CONTENT), pero el manejador global la intercepta y fija el 404 en el ProblemDetail.

      400Bad Request

      BadRequestException

      Lanzada por los métodos validar de las clases base. GlobalErrorHandler.badRequest responde 400 con el título «Petición errónea».

      • El libro es obligatorio
      • El ISBN es obligatorio
      • El título es obligatorio
      • El autor es obligatorio
      • Debe haber al menos un ejemplar
      • La categoría es obligatoria
      • El nombre es obligatorio

      Colección de Postman

      La carpeta postman/ guarda la colección Biblioteca Decroly en formato YAML, versionada junto al código. Tiene una petición por cada ruta de la API, con los cuerpos JSON de ejemplo ya escritos.

      {{baseUrl}}
      http://localhost:8080
      {{categoriaId}}
      id de categoría para GET, PUT, DELETE y libros por categoría
      {{libroId}}
      id de libro para GET, PUT y DELETE
      {{autor}}
      nombre del autor para /api/libros/autor/{autor}

      Las variables se definen una vez en la colección; cambiar baseUrl basta para apuntar a otro servidor.

      Lo que demuestra el proyecto

      1. Capas con una sola responsabilidad. Los controladores enrutan, los servicios deciden, el dominio guarda datos.
      2. Programar contra interfaces. Los controladores reciben LibroService y CategoriaService por constructor.
      3. Lógica reutilizada por herencia. Una clase base y varias fuentes de datos iniciales.
      4. Entrada separada del modelo. Los DTO evitan que el cliente fije id o disponibles.
      5. Errores coherentes. Un manejador global y respuestas ProblemDetail.
      6. Una API que se explica sola. OpenAPI y Swagger UI generados desde las anotaciones.
      7. Configuración tipada. Las propiedades biblioteca.* llegan a los servicios como un record.
      8. Documentado y listo para probar. README con el flujo de la aplicación, un README por paquete y la colección de Postman.

      Cómo arrancarlo

      Requiere Java JDK 25. El proyecto incluye Maven Wrapper.

      cd biblioteca-decroly
./mvnw spring-boot:run        # Linux / macOS
.\mvnw.cmd spring-boot:run    # Windows

      La API queda en http://localhost:8080 y Swagger UI en http://localhost:8080/swagger-ui/index.html. Para probarla, importa la carpeta postman/ en Postman. Las pruebas se lanzan con ./mvnw test.
